# EV Fleet Monitoring System

Streamlit dashboard for monitoring a 50-car EV fleet — admin fleet analytics
+ driver-facing range prediction. Built over a 3–4 day sprint by 8 people.

## Quick start

```bash
git clone <repo-url>
cd ev-fleet-monitor
python -m venv venv
source venv/bin/activate        # Windows: venv\Scripts\activate
pip install -r requirements.txt

# Generate the processed dataset (only needs to be run once, or after
# data_prep.py changes)
python src/data_prep.py

# Run the app
streamlit run src/app.py
```

## Dataset schema (locked Day 0 — see `data_prep.py`)

Source file has 10,000 rows, 50 unique cars, 200 records/car, Jan–Aug 2025,
zero missing values. Key columns after processing:

| Column | Notes |
|---|---|
| `Car_ID`, `Driver_ID`, `Driver_Name` | fleet identifiers |
| `Company`, `Model` | Tata, Suzuki, Hyundai, MG, Mahindra / 10 models |
| `Battery_Remaining_Percent` | **derived** = 100 - `Battery_Pct_Used`. Use this one, not `Battery_Pct_Used`, for anything battery-related |
| `Fleet_Status` | **derived**, = `Live_Car_Status`. This is the single source of truth for Running/Charging/Idle/Under Maintenance. Don't use `Current_Status` (a separate, coarser field kept only for reference) unless you have a specific reason — ask the team first if you think you need it |
| `Driving_Style` | Rash / Safe — for driver habit analytics |
| `Driving_Mode` | Highway / City |
| `Revenue_INR`, `Exact_Maintenance_Cost_INR`, `Electricity_Cost_INR` | financials |
| `Est_Full_Range_km` | ML model target |
| `City`, `Area`, `Location`, `Latitude`, `Longitude` | already-populated location data, no simulation needed |
| `Month`, `Month_Num` | derived, for the admin month filter |

**If the schema changes, update this table in the same PR.**

## Branching model

- `main` — always demo-able, protected
- `dev` — integration branch, merge PRs here first
- Feature branches: `feature/<squad-name>`, e.g. `feature/ml-model`, `feature/admin-dashboard`

Daily flow: work on your feature branch → PR into `dev` → QA/repo lead reviews
and merges → end-of-day merge `dev` into `main` once smoke-tested.
